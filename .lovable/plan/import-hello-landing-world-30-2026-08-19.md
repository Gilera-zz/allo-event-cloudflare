# Import hello-landing-world-30

Bring the uploaded project into this workspace as the running app, reusing its existing hosted backend.

## What gets imported

- All app source: routes (public landing page + `/login` + the full `/admin` area: leads, projects, staff, schema, timesheets, availability, designs, mass mailing), components (booking section, projects section, site header, admin sidebar), shadcn UI library, hooks (auth, theme, mobile), i18n strings, Supabase client, styles, and the design tokens from the zip.
- Static assets: favicons, app icon, partner logos, logo image.
- The SQL migration files, kept as reference under `db/migrations` (not re-run, since the existing database already has them).

## What is skipped

- The Netlify function for booking notifications, plus `netlify.toml` and `public/_redirects` — per your choice, notifications are left out for now.
- The zip's `.git` metadata and lockfile-level tooling that conflicts with this workspace.

## Backend

The app keeps talking to its current hosted database. The URL and publishable/anon key from the zip's `.env` are stored as project secrets (`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_ANON_KEY`, plus server-side `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY`) rather than committed in a file, so existing data, logins, and leads continue to work unchanged.

## Technical notes

- Stack already matches: TanStack Start v1 + Vite 7 + React 19 + Tailwind v4, so the routes and `vite.config.ts` (SPA mode with `/index` prerender) transfer directly.
- Existing placeholder `src/routes/index.tsx` and `src/routes/__root.tsx` are replaced by the zip's versions; `routeTree.gen.ts` is regenerated by the dev server.
- Dependencies from the zip's `package.json` are installed (Supabase JS, recharts, date-fns, day-picker, embla, vaul, cmdk, radix set, etc.).
- Any booking-form code path that called the Netlify notification endpoint is left writing to the database only, with the notification call removed so submissions don't error.
- After import: verify the landing page renders, the login route loads, and one admin list fetches data.

Run a build/typecheck pass and load `/`, `/login`, and `/admin` in the preview to confirm no import or runtime errors.
